# What should I check first for Security And Permissions?

Start from the exact secured object: page, block, entity, REST key, group role, or workflow action. Compare inherited page security, block security, explicit Auth rows, group membership, and the current user's person alias before deciding why access is allowed or denied. For public or staff-facing changes, verify both view and edit paths because route visibility does not prove record-level permission.
